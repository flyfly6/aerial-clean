# 跨包思维指南

本仓有两个包（`lite/` 桌面、`tools/` 安装器），它们代码无关、顺序强耦合。改任何一边都问三个问题。

| 指南 | 用途 |
|---|---|
| [代码复用](code-reuse-thinking-guide.md) | 动手前先确认这段逻辑上游或本仓是否已有 |
| [跨层数据流](cross-layer-thinking-guide.md) | 数据/状态穿过脚本与 App 边界时的契约 |

## 1. 顺序

安装器的顺序是：装 APK → 确认 Home 已切换 →（可选）禁用原桌面 → 跑停用列表。桌面改动如果影响"能否被设为 Home"（包名、Activity 名、`CATEGORY_HOME` 声明），`tools/` 侧的验收脚本与文档必须同步改。

## 2. 契约

两边唯一的契约是：**包名 + HOME Activity 全名 + APK 产物路径**。

- 包名改动 → 安装器、还原脚本、文档、`bind` 类命令全部要改。
- 产物路径改动 → `install.sh` 的默认值要改。

契约写在 `lite/app/build.gradle.kts` 与 `install.sh` 顶部，只有这两处是权威。

## 3. 还原

桌面装了要能卸载，包禁了要能恢复。任何新增的持久化状态（写入的设置、安装的包）都必须出现在还原路径里，否则"一条命令还原"就是假的。
